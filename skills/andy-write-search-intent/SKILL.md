# Andy Write — Search Intent V1.1 (pilot)

Determine what a searcher is trying to accomplish, what kind of page answers that need, and whether a proposed or existing article actually serves it. This skill is **advisory only**; it does not create or change an article, replace Owner requirements, or update Andy Write runtime.

## Workflow

1. **Lock scope.** Record `target_keyword` exactly as provided, `site`, `audience`, `market_country`, `language`, `device`, date and immutable Owner/Article Scope Contract identifier (if supplied). Do not silently rewrite a keyword, choose a different product category, or change an Owner P0 requirement. If the primary market is missing, ask or state an explicit assumption; never infer it from the operator's physical location. For PairDoll tests, assume US / English / mobile **only when confirmed by the task or labeled as an assumption**.
2. **Collect SERP evidence.** Prefer the target-market Google organic top 10 from a SERP provider export or full screenshot. Record ranks, **final destination URLs** (not Google `/goto` redirects), titles, page types, dates, collection method and time; open 3–5 representative pages for scope and format. Keep raw, irrelevant and unstable rows for quality audit, but exclude them from the intent-majority count with reasons. If a named tool exists (Search Atlas, OpenSEO, etc.), use only a configured, authorized source. Generic web search is a legitimate exploratory fallback **but is not a verified, localized Google top 10**. Never invent rank positions, search volume, keyword difficulty, CTR, AI Overview presence, or People Also Ask questions.
3. **Grade evidence quality before drawing conclusions.** Read `references/serp-quality.md`. For OpenSEO merged results, `rank` is a merged-row index, **never** the observed Google rank: use `bestPosition`; `seenIn=1` across three reads is weak evidence. Run `scripts/grade_serp_evidence.py` on the raw or normalized sample when available. Require at least five relevant, independently identifiable organic pages with verified final URLs and adequate observation stability before `verified`. Treat unknown page relevance, unverified final URL redirects, sparse results and inconsistent branded searches as `provisional` and gate `REVIEW`. `blocked` requires no usable evidence. Independently verify an official brand domain from its first-party site; lookalikes do not establish navigational intent or brand ownership. Never silently classify a lookalike as the official site. On `blocked`, abstain from a substantive verdict. On `provisional`, label conclusions and avoid top-ten claims.
4. **Decode the intent.** Group observed pages as `guide`, `comparison`, `review-list`, `category`, `product`, `forum`, `homepage`, `other`; separately classify `informational`, `commercial-investigation`, `transactional`, `navigational`, or `mixed`. Give the observed count and top exemplars; do not generalize an observed set of 3 to a claim about Google's top 10. State searcher's immediate question, buyer-journey stage, the useful next click, expected format and scope. Note secondary intents. When page types are split, report `mixed` rather than manufacturing a majority.
5. **Check a page only if supplied.** Read the *actual* article, URL, or outline. Compare: (P0) page's actual user job and audience/buyer stage; (P1) main angle and first-screen answer; (P2) subtopic coverage, format and next click; (P3) freshness and original evidence. Distinguish `Match` (user job, angle, depth, next click substantially aligned), `Partial` (same broad user job/stage but an important modifier, answer, list, filter or format is missing), `Mismatch` (different primary user job, incompatible buyer stage, unrelated brand identity, or a single product that cannot answer a comparison/how-to), and `Unassessable` (missing draft or evidence). **Do not turn a format preference into an automatic Mismatch:** a comprehensive buying guide containing relevant product examples can be Partial for a `best X` shortlist query if it still helps the same purchase decision. A materials guide comparing both options' meaningful pros/cons and offering a choice can be Match for `A vs B` without a comparison table; evaluate substance, not table markup. An incidental one-line mention/link without substantive coverage is not enough for Partial. Preserve important literal modifiers (`realistic`, `full size`, `official`, year, audience), and never silently change the Owner keyword. A correct guide with an off-target editorial angle is **Partial**, not automatically Mismatch.
6. **Prescribe a fix at the right stage.** For a partial page give at most 3 priority-ordered *diagnostic* recommendations with query → missing need → observed evidence → smallest fix. For Mismatch specify target page type or a justified retargeting recommendation; do not secretly change the Owner keyword. Do not rewrite an article, generate outreach, edit Notion or contact its author as a side effect of QC.
7. **Produce two artifacts.** `intent_report.md` for human review and `intent_contract.json` for the next Andy Write stage. Follow `references/contract.md` exactly. Include citations/links, evidence limitations, the gate (`PASS`, `REVIEW`, `BLOCK`), and what the Owner is being asked to approve. Attach `evidence.quality` to verified contracts with relevant/stable/final-URL counts. Validate JSON by running `python3 scripts/validate_contract.py <intent_contract.json>` from this skill directory; fix any validation failures. If the task is exploratory and no file is requested, an equivalent structured answer is acceptable.

## Quality gates and stopping rules

- **PASS:** credible, independently verifiable observed evidence including relevant stable results and final destination URLs, unambiguous intent, outline/page follows required page type + main angle, Owner P0 preserved. A `verified` Google top-10 export is preferable; `provisional` evidence cannot authorize unattended production publication.
- **REVIEW:** credible but mixed, ambiguous, incomplete or geographically unverified evidence; or a `Partial` existing page. Owner chooses before a brief is frozen.
- **BLOCK:** zero result evidence, a `Mismatch` that requires changing product/page type, an unresolved conflict with an Owner contract, missing source article when asked to audit, or invented evidence.
- **SERP-feature discipline:** `observed`, `not-observed`, `unknown`. Generic web search means `unknown` unless the feature itself was explicitly returned. `not-observed` is never equivalent to absent.
- **No mechanical word counts.** Recommend subtopics, depth and artifacts according to observed pages; do not make a length or keyword-density threshold a purported ranking rule. Explicit Owner keyword-count instructions remain separate and must be preserved, not quietly replaced.
- **No baseless promise:** a strong intent match does not prove Google ranking ability or commercial viability. No unsupported numeric claims about CTR, competition, or Google policy.
- **Independent scope:** the prior Mary draft was a calibration sample, not an authorization to continue Mary writing tasks. Use anonymous or public benchmark cases for future tests unless expressly directed otherwise.

## Validation & references

- `references/contract.md` — read for field schema, examples and gate rules before producing a machine-readable contract.
- `references/serp-quality.md` — read for OpenSEO result semantics, stability, direct URL and official-domain gates.
- `references/benchmark.md` — read for a dated, exploratory eight-case search sample and failure modes. Treat as **test fixtures**, never current rankings.
- `scripts/validate_contract.py` — dependency-free deterministic schema and evidence-integrity checks; run with `--self-test` to check the validator itself.
- `scripts/grade_serp_evidence.py` — deterministic quality gate for a normalized SERP snapshot. This is an evidence checker, not a substitute for human editorial labeling.

**Pilot status:** manual invocation only. Do not integrate with Andy Write's Research → Source → Outline → Draft → Editor → Quality pipeline, mutate Article Scope Contract, or declare production PASS without Owner UAT.
