# Andy Write Outline — R2
Read the topic clusters, source references, brand voice, existing URL map and evidence statuses.
Create H1, cover image slot, introduction plan (opening; bold concise answer; transition), TOC, claim slots with IDs, 4–7 question-form H2 sections, image plan after each H2, Conclusion and link plan.
Three-paragraph section cadence is a starting point, not mandatory repetition.
Never insert an unsupported Claim as a publishable assertion. Output outline.md and section-plan.json.

## V1.2 source-adaptive H2/H3 — topic mode and QC experiment

For user/team-owned articles with real Markdown heading hierarchy, set
outline_mode = source_hierarchy_v1 and pass the ENTIRE original to
section_plan. The checker validates the source SHA-256 against the R1 catalog,
transforms actual H2 headings into natural editorial questions, preserves
original H3 topics and attaches relevant real source segment IDs.

This mode is opt-in and does not alter frozen legacy Unboxing plans. It
does not invent six delivery-day sections for a torso-use or other article.
Missing actual source headings or mismatch hashes fail closed. Real source
product-care warnings trigger MANUFACTURER CHECK REQUIRED rather than automatic
reuse. A heading discussing an unsafe method remains a review topic and
must not become an endorsed user instruction.

Do not import KissSelf's section headings as a new article template: only
its measurable QC structure and topic intent can inform which checks are
worth including. Never force H3/table/FAQ counts to mimic a competitor.
No new media, images or videos. No Codex CLI for outline research.
