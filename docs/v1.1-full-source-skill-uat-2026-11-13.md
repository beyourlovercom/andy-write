# Andy Write V1.1 — Full-source rewrite contract UAT

Owner P0: Skill-first / Evidence-based / Version-rollback.
Date: 2026-11-13.
Scope: Reusable input-source integrity improvement for article rewriting, not a one-off PairDoll repair.

## Root cause

Previously prepare_prompt() selected at most four 260-character excerpts per topic cluster. This verified that an Owner reference file existed, but a large fraction of the actual original article was not present in the model prompt, so key details or short paragraphs could be omitted from rewriting context.

## Reusable V1.1 correction

- Shared module andy_write/rewrite_contract.py now embeds the complete original, unchanged, in a labeled untrusted-data block with source URL, SHA-256 and version identifier.
- The owning andy-write-draft Skill requires full source text. Old excerpts remain optional navigation aids, never substitutes for the complete Owner article.
- All rewriting backends (Codex CLI and optional OpenAI API) validate complete source, original hash, prompt hash and contract version before launching a model. Legacy excerpt-only prompts, changed text, duplicated delimiters, oversized sources or stale prompt hashes are rejected.
- Limit: 160,000 original source characters. Over-limit inputs must STOP rather than silently truncate; an approved future chunking Skill is a separate scope.
- A new contract changes the writing-prompt fingerprint and intentionally invalidates prior generated-draft cache hits, while keeping old drafts available for comparison.
- The R1 run manifest records source and prompt SHA-256 plus contract version; successful rewrite report stores source-input completeness proof.
